ESP32-C6 BLE LINK GPIO
======================

在用户工程中保留原有 AT/透传功能，通过 NimBLE GAP 旁路监听器输出 BLE 连接状态。
不替换 BLE 收发回调，不通过解析串口提示文本推断连接。默认不占用 GPIO。

命令
----

* ``AT+LINKGPIO=<gpio>[,<save>]``：设置引脚。``save=0`` 或省略为仅本次运行；
  ``save=1`` 保存到 NVS。``gpio=-1`` 禁用。命令以标准 AT 的 CRLF 结尾。
* ``AT+LINKGPIO?``：返回 ``+LINKGPIO:<gpio>,<link>,<active_count>,<fault>``。
  ``link`` 是软件最近成功设置的输出状态，不是引脚电压测量；``fault=1`` 时
  有初始化、驱动、NVS 或协议栈生命周期错误，应停止依赖此状态并检查。
* ``AT+LINKGPIO=?``：查询语法。示例 ``AT+LINKGPIO=18,1`` 仅表示用法，
  不代表已经确认用户的板级 GPIO18 可用。
* ``AT+LINKGPIO=-1,1``：禁用并保存。以前使用的输出脚保持低电平直到重启，
  请勿在本次运行中把这些脚复用于其他外设。

GPIO2/3/10/11/14/18..23 是候选范围，还会排除实际 AT UART 引脚、定制日志串口
以及 IDF 已保留的 GPIO。GPIO0/1 留给 RTC，4/5/8/9/15 为启动相关脚，6/7 是
默认 AT 串口，12/13 是 USB，16/17 是日志串口，24 以上留给 flash/封装资源，
均不允许用作 LINK。最终还必须核对实物模块引脚及板上连接。

状态与休眠
----------

实际 GAP CONNECT 成功才记为连接；重复、失败、无效句柄事件不增加计数。
多个连接中只要还有一个，LINK 就保持高。最后一个连接断开才拉低。
禁用输出时仍跟踪连接，再启用可正确反映已有连接。

* 保留连接的轻睡眠保持 LINK；关闭输出脚的独立睡眠复用配置，唤醒不制造连接。
* NimBLE deinit、重启及深睡眠前清除连接并拉低，随后忽略竞态中的 CONNECT。
* 深睡眠唤醒相当于新启动，保存的引脚重新加载，连接状态从零开始。
* AT 配置、NVS 操作与 GAP 状态更新使用互斥锁；先预置输出锁存值再使能新输出。
* 写 GPIO 失败会保留错误状态；NVS 失败返回 ERROR 并尝试恢复先前运行配置。
  发生存储错误后，应重新查询并在重启后确认持久化值，不能把 ERROR 当作成功。

保存的引脚在 AT core 启动前、UART/NVS 初始化后加载。``AT+RESTORE`` 是预编译
核心实现，本扩展不改变它的清理范围；明确清除此功能请用 ``AT+LINKGPIO=-1,1``。

用 GPIO 接 STM32 BOOT0 时，需外部下拉保证 C6 未启动、复位或断电期间的电平。
软件不保证这些阶段的引脚电压，也不能代替独立供电及反向供电检查。先让 BLE
连接并确认 LINK 稳定，再给 STM32 上电。无自动 STM32 电源控制或复位控制。

RTC 输入检查
------------

``AT+RTCCLK?`` 返回例如 ``+RTCCLK:"EXT_OSC",32768``，表示本次运行选中的
RTC 时钟源及标称频率。若返回 ``RC_SLOW`` 则不能认为外部时钟已成功使用。
该命令不是频率计，不能证明外部波形、精度或长期稳定性。

本工程有源 32768 Hz 输入使用 GPIO0 / XTAL_32K_P。正常和静默配置均选择
``CONFIG_RTC_CLK_SRC_EXT_OSC=y``，校准周期保留原来的 1024；不使用无源晶体的
``EXT_CRYS``，也不使用固定版本 Kconfig 中不存在的 ``RTC_CLK_SRC_CUSTOM``。
详情见同目录 ``RTC_32768_REVIEW.md``。

实现依据与验证
--------------

固定 ESP-IDF 提交 ``4dbfecac7e3b196d3f6826b3db2fdd5a23708e0d``，其 NimBLE
子模块 ``139cada0ae932957fa06ba37d17e3c9c2c95c773``。监听器在
``nimble_port_init`` 成功后、host task 启动前注册；deinit 前注销，避免动态 GAP
存储释放后访问。host reset 会逐连接派发 DISCONNECT。链接 wrap 仅用于 C6/NimBLE。

主机测试编译实际 ``main/link_gpio_state.c``，覆盖多连接、满容量、重复/失败、
未知断开、禁用再启用、同脚无低脉冲、GPIO 错误恢复和活动连接期间的保存失败回滚。
GitHub Actions 的 C6 任务还检查最终 sdkconfig 和 map/ELF 中的接口及 wrapper。
离线逻辑和在线编译不能代替实机电平、睡眠、透传及 BOOT0 联调。
